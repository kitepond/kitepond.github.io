Why our language switch alone does not give you Vietnamese SEO

A browser-side EN/VI switch does not give a search engine a second language to index. Here is how separate static pages, canonical and hreflang fix that on GitHub Pages.

Short answer: a language switch that runs in the browser is not enough to make a second language show up in search. This post explains why and shows the pattern we use on this very site. It makes no claims about rankings.

What a client-side language switch does

The switch in our Yaylish template swaps the page text in the browser and remembers the choice in localStorage. The HTML file on the server never changes: it ships in one language, and everything else happens after the page loads, on one visitor's device.

Why search engines only see one language

A crawler fetches the URL and reads the HTML it receives. It does not click your language button and it does not share your browser's saved choice. So it reads the language the page ships with, and there is only one URL for both languages, so there is nothing separate to index for the other language.

The fix: separate pre-rendered pages

  1. One URL per language. Each page has its own static HTML file with the text baked in. On GitHub Pages we cannot do server redirects, so we keep Vietnamese at the root and English under /en/.
  2. Self-referencing canonical. Each page's rel="canonical" points to its own URL.
  3. Reciprocal hreflang. Each page lists every language version, including itself, using absolute URLs. If page A points to page B, page B must point back to A.
  4. x-default. Name a fallback page for visitors whose language you do not target.
  5. Same set in the sitemap. List each URL and its alternates in sitemap.xml.

A worked example from this site

Our landing pages are a Vietnamese page at / and an English page at /en/. The head of the English page contains:

<link rel="canonical" href="https://kitepond.github.io/en/">
<link rel="alternate" hreflang="vi" href="https://kitepond.github.io/">
<link rel="alternate" hreflang="en" href="https://kitepond.github.io/en/">
<link rel="alternate" hreflang="x-default" href="https://kitepond.github.io/">

The Vietnamese page carries the same three alternate lines and a canonical pointing to https://kitepond.github.io/. The same structure repeats for each page pair, for example the Vietnamese template page and its English counterpart.

A checklist

  • Every language has its own URL and its own baked-in HTML text
  • <html lang> matches the page's language
  • Canonical points to the page itself, not to the other language
  • hreflang tags are reciprocal, absolute, and include the page itself
  • Sitemap lists all URLs; internal links connect the language pairs
  • A visible link lets visitors switch language (ours is the EN / VI button in the header)
