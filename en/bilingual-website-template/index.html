Bilingual HTML + Tailwind website template with an EN/VI switch

Yaylish is a static HTML + Tailwind template with an EN/VI switch that remembers the visitor's choice. All text sits in two language files, and a third language can be added. It comes with an honest limit: the switch alone does not give Vietnamese SEO.

How the EN/VI switch works

Every page in Yaylish has an EN / VI button. The visitor's choice is saved in the browser (localStorage, key yaylish.lang), so the next page opens in the same language. All text lives in two files, assets/i18n/en.js and assets/i18n/vi.js, with 330 keys each. A small script, npm run check (needs Node.js), verifies that both files have the same keys.

The honest SEO limit

Because the switch runs in the browser, the static HTML ships in English and search engines index the English text. A crawler does not click your language button, so Vietnamese text added by the switch is not what it indexes. This is a known limitation of the template, not a bug. The bundled docs describe two fixes: bake your default language into the HTML (see the “SEO basics” section of the docs), or build a separate /vi/ copy with Vietnamese baked in. A script that renders one static page per language is not included.

How our own site handles it

This studio site does not use the switch for SEO. It has separate static pages: Vietnamese at the root and English under /en/, each with a self-referencing canonical and reciprocal hreflang tags. We explain the pattern step by step in Bilingual static site SEO: hreflang EN/VI.

Adding a third language

Copy assets/i18n/vi.js to a new file, translate the values, and add the new code to language.available in site.config.js. The docs include a worked example. Remember that each extra language needs its own review by a native speaker.

Honest notes

  • All content in the template is sample data. Teachers, parent quotes, tuition, timetable, addresses and bank details are placeholders – replace them with real information.
  • The trial form only sends data after you connect a form provider (Formspree, Netlify Forms or your own endpoint). By default it validates input and shows a demo-mode message.
  • The language switch runs in the browser, so Vietnamese search indexing needs extra work as described in the bundled docs (make Vietnamese the baked-in default, or make a separate copy).
  • Not included: a payment gateway, a CMS or a student-management system. The VietQR block is an information panel with a QR image you supply.

FAQ

Can I make Vietnamese the default?

Yes: set language.default to vi and bake the Vietnamese text into the HTML as described in the docs, or build a separate copy.

Does the switch need a server?

No. It runs entirely in the browser; there is no server-side component.

Can I remove a language?

Yes. Remove it from language.available and keep a single language file.
